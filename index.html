The pipeline

Six stages, three of them real model calls, two deterministic. The agent steps reason; the deterministic steps are the ones allowed to say no.

01
CRAWL deterministic
Fetched prommer.net, wetheflywheel.com, llms.txt and four competitor sites. Parsed 26 weeks of ticker data. Froze a 23,798-character grounding corpus, hashed.
0.0s
02
EXTRACT agent
Read the raw page text, emitted a 16-entry proof ledger — each claim carrying the exact source substring it came from. Inference forbidden.
21.3s
03
AUDIT agent
Diffed the ledger against the live llms.txt. Found 6 gaps where proof exists on-site but is absent or stale in the machine layer — 3 rated high.
35.7s
04
GENERATE agent
Wrote the fix: an llms.txt “Proof of practice” section, a schema.org Person block, and a press-booker brief — restricted to ledger facts only.
80.3s
05
VALIDATE gate
Every number and proper noun in the generated output must appear verbatim in the frozen corpus. 25 checks, 0 ungrounded. A failure feeds the offending tokens back to stage 04 and regenerates, up to 3 attempts.
0.0s
06
PUBLISH deterministic
Wrote the run record — stage timings, ledger, findings, every individual check — to run.json. This page is that record.

The gate has to be able to fail

A validator that passes everything is decoration. So I ran a negative control: took the passing artifact, injected the three hallucinations an LLM most plausibly produces here — an inflated commit count, an invented outlet, and one true claim as a decoy — and re-ran the same validator, unchanged.

Where this is still weak

  • The entity check only catches multi-word proper nouns. In the negative control it caught “Forbes Technology Council” but missed a bare “TechCrunch” — single-token outlets slip through. Next fix: a known-entity list plus a single-token capitalised sweep.
  • Grounding is verbatim string matching, so it proves a number came from the page — not that the page was right. It's a fabrication gate, not a truth gate.
  • The crawl reads server-rendered HTML. The ticker only parsed because its values ship in the markup; a fully client-rendered widget would need a headless browser at stage 01.
  • Stage 03's severity ranking is the model's judgement and is not gated. I'd want a human sign-off on ordering before this ran unattended.
